# v1.0.0-devnet.2 — Phantom and MetaMask checkout

A devnet community preview, not a real merchandise launch or production payment processor.

## New

- Explicit **Connect Phantom** and **Connect MetaMask**, followed by a separate wallet approval for the exact cart total. MetaMask uses its Solana desktop-extension account, not an Ethereum address. MetaMask mobile does not support Solana devnet.
- Wallet Standard discovery plus lazy-loaded official MetaMask Connect, with SDK analytics disabled. Transaction assembly uses Solana Kit and the generated SPL Token client; no legacy Solana web3/SPL-token browser bundle.
- Devnet genesis-hash verification, mint/decimals and balance checks, transaction simulation, exact TransferChecked, idempotent recipient token-account creation, reference and memo.
- The page submits the signed, unchanged transaction only to the verified devnet RPC. It shows a signature/Explorer link, never an order-paid or fulfilled claim. Ambiguous submission retains the signature and disables another payment for that intent.
- Account-change, cart-change, signing-expiry and reservation-expiry guards. QR/handoff remains an alternative, with an explicit network warning.
- `npm run devnet:fund -- PUBLIC_SOLANA_ADDRESS 100`: operator-side transfer of test tokens plus 0.02 devnet SOL from an existing local demo payer. No keys or faucet authority in the browser or release.
- Optional, backward-compatible `payment.rpcUrl`; older schema-version-1 configs keep using the public devnet RPC. Updated setup/manual and bundled dependency license report.

## Verification

Unit checks decode the actual transaction independently with legacy web3 and verify its exact bigint amount, account destinations, reference, memo and signer. Browser checks use simulated Wallet Standard providers for Phantom and MetaMask and exercise connection, signing, submission, insufficient balances, mainnet rejection, wallet rejection, modified transactions, changed accounts, expired blockhashes and ambiguous submission. These automated mocks do **not** certify installed extension versions.

The shared browser transaction builder also sent one base unit (0.000001 TEST DRU) on live devnet from the existing disposable demo payer. The transaction finalized successfully: [public smoke-test transaction](https://explorer.solana.com/tx/3bqYXaJyfC7oSVReTJuZ9EsLg33oiSn3i86XDb56cWU5wXpPBeZjJsZ3DmAMyZL2ymybcU1RHCitxbPBRa11CAuA?cluster=devnet). This was a local test-key signature, **not** a Phantom or MetaMask extension approval. Real-extension acceptance remains a separate manual check.

## Limits and security notes

- Requires classic SPL tokens in the buyer's associated token account and at least 0.01 devnet SOL. Token-2022 and MetaMask mobile devnet are not supported. In-app preview browsers may not expose installed extensions.
- Public RPC services may be rate-limited or unavailable. A custom browser RPC URL is public; never put a secret there. CLI reconciliation still uses its separately configured `SOLANA_RPC_URL`.
- Signature/session/receipt state is in memory. Save the signature before refresh. No global idempotency, settlement verification, automatic fulfillment, real shipping/tax, mainnet checkout, voting, profit splits or buyback/burn execution.
- The MetaMask SDK may store its own public connection/session metadata and use vendor services. Its analytics are disabled here; wallet secrets remain in the wallet.
- `npm audit --omit=dev` at release preparation reports six affected packages (moderate) tracing to transitive `uuid` advisory [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq), with no automatic fix offered for the current MetaMask dependency tree. Local Solana tooling retains the bigint-buffer, stream-json and uuid advisories disclosed in devnet.1. These have not been independently audited or declared unexploitable. Use disposable devnet wallets only.
- Third-party reference merchandise and images remain excluded from the code/artwork MIT license. Obtain permission or replace them before a commercial launch.

Download the source ZIP for development and local inventory, or the static ZIP for a prebuilt website. Both include the manual, community proposal, licensing notices and checksums. Neither includes test keys, local databases or node_modules. The default config still points to the upstream test mint and recipient—fork owners must configure their own.
