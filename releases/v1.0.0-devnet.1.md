# v1.0.0-devnet.1 — Community preview

The first downloadable release of Solana Token Storefront, contributed for token holders to try, fork, and improve. Run it on your own computer and explore whether a merchandise checkout is a useful way for your community to use its token.

## Choose a download

- **Source ZIP:** the complete editable project with storefront, Node/SQLite inventory service, scripts, tests, user manual, and community proposal. Recommended for local use and customization. Requires Node.js 22.12+ and `npm ci` after extraction.
- **Static ZIP:** the prebuilt website, local product images, public configuration, and documentation under `docs/`. Serve it with a local HTTP server or your own static host. This archive does not include a running inventory service.
- **SHA256SUMS.txt:** SHA-256 checksums for both ZIPs.

The release includes no private keys, local inventory database, Git history, or installed dependencies. GitHub also provides its standard source-code archives for the tag.

## Start locally

Extract the source ZIP, open a terminal in `solana-token-storefront-v1.0.0-devnet.1`, then run:

```sh
npm ci
npm run validate-config
npm run dev
```

Open Vite's printed localhost URL. For tracked stock, follow the included `USER_MANUAL.md` to enable service mode, receive inventory, and start `npm run inventory:serve` in another terminal.

## Included

- Eight DRU reference products with 37 variants, plus three non-purchasable original concepts.
- Cart, variant and quantity controls, local cart persistence, and exact token arithmetic.
- Solana Pay QR and wallet handoff on devnet.
- Optional local SQLite inventory, expiring stock reservations, canonical order snapshots, and merchant CLI.
- Manual finalized-payment reconciliation and explicit fulfillment status.
- Community proposal, local user manual, and an interactive hypothetical campaign case study.
- Configuration validation that supports a fork's own recipient, mint, inventory mode, and catalog.

## Preview boundaries

This is an unofficial **devnet prerelease**. The default configuration uses the upstream demo's receiving wallet and `TEST DRU` mint. Replace those public settings for your own test setup. Nothing in this release offers real merchandise delivery or enables mainnet checkout.

The default static mode does not reserve stock or verify payment. Service mode requires the merchant to run the included Node process and manually reconcile payment before the reservation expires. The browser does not show a verified success state or automatically retire an expired QR. Read the manual before a payment rehearsal.

Shipping details, refunds, tax, production payment hardening, automatic monitoring, PAID integration, voting, community profit splits, buybacks, and burns are outside the implemented flow. The proposal discusses possible future community choices; it does not make a financial commitment.

Code and original concept art use the MIT license. Third-party names, catalog material, and reference product images are excluded; see `NOTICE.md` before reuse.
