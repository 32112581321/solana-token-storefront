# v1.0.0-devnet.3 — Public roadmap and settlement proposal

A community-review release, not a mainnet launch or a request for funds.

## New in this release

- An expanded merchant-settlement and USDC-reserve proposal covering authorized product/order integration, bounded DRU conversions, realized-fee contributor incentives, valuation, losses, withdrawals, and approval gates.
- A public roadmap with delivery filters, search, dependency navigation, acceptance checks, evidence, and downloadable JSON, linked from the storefront and case study.
- A repo-owned graph with 31 draft Work definitions, 19 leaf Tasks, one proposed Arena, and 52 relationships. Canonical vocabulary is pinned to Devgraph ontology 0.6.0 and its bundle digest.
- Deterministic, unsigned native Work/Arena create envelopes and an operator import guide. No private Devgraph mutations or automatic synchronization.
- Shared browser/CLI validation and new unit/browser coverage; the static release includes the roadmap, graph, request pack and both design/maintenance documents.

## Try it

Visit the [public roadmap](https://32112581321.github.io/solana-token-storefront/roadmap.html) or download the source ZIP, run `npm ci`, then `npm run dev`, and open `/roadmap.html`. Edit `public/roadmap/graph.json`, run `npm run roadmap:export`, then `npm run validate-roadmap`. No Devgraph installation is required.

The static ZIP contains a prebuilt site; see `START_HERE.md`. Verify ZIPs using `SHA256SUMS.txt`. Repository-relative Markdown links are designed for the source repository; read the source bundle or GitHub for linked code and evidence.

## Boundaries remain unchanged

No live merchant connector, pooled settlement vault, public deposits, swaps, contributor reward contract, voting, or buyback/burn is implemented. Current payments still go directly to the configured recipient on **Solana devnet**. The release does not change payment, catalog, or inventory contracts. Actual Phantom/MetaMask extension rehearsals remain an explicit next task; automated wallet mocks are not that proof.

The reserve proposal requests feedback, not capital. No guaranteed APY, principal protection, redemption availability, token-price outcome, creator approval, or launch date is represented. Mainnet, public-money custody, real orders, and community fundraising require separate implementation, agreements, legal/security review, and operating controls.

Existing dependency advisories and unaudited-preview limitations from v1.0.0-devnet.2 remain; no wallet dependencies were changed. Code/original art licensing and third-party exclusions remain in `LICENSE.md` and `NOTICE.md`.
